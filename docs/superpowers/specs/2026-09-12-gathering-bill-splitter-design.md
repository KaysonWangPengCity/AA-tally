# 聚会记账 AA 结算 App 设计文档

## 概述

一个手机网页应用（PWA），帮助用户在聚会当天多次记账、灵活分摊，并一键汇总每个参与者应付金额。

**核心场景**：聚会当天由用户统一买单 → 依次录入多笔消费、设置每笔的参与人和分摊方式 → 一键汇总每人应付多少。

## 决策摘要

| 维度 | 决策 | 理由 |
|---|---|---|
| 使用方式 | 单用户记账，无需账号/登录 | 只有用户本人录入，最简单 |
| 分账规则 | 默认均摊 + 可微调 | 既能快速记账，又能处理个别例外 |
| 参与人管理 | 维护固定朋友名单 | 避免每次重复输入 |
| 平台形态 | 手机网页 / PWA | 跨平台、开发快、适合先做原型 |
| 数据存储 | 纯本地 localStorage（含 JSON 导出/导入） | 开箱即用、隐私安全、离线可用 |
| 结果产物 | 每人应付清单 + 历史账单 | 满足核心需求，不引入群收款文案/进度追踪 |

## 界面流程

5 个页面，按「建聚会 → 记账 → 结算」顺序：

### 1. 聚会列表（历史账单）
- 标题「我的聚会」
- 聚会卡片：名称 + 人数 + 状态（进行中/已结算）+ 总金额
- 右下角「＋」新建聚会

### 2. 新建聚会
- 输入「聚会名称」
- 「谁参加了」：从固定朋友名单用 chip 勾选到场人
- 按钮「开始记账」

### 3. 聚会详情
- 标题 + 到场人标签
- 消费流水列表（每笔：名目、参与人数、金额）
- 汇总：共 N 笔 · 总消费 ¥X
- 按钮「＋记一笔」「一键结算」

### 4. 记一笔
- 金额 / 备注
- 「参与分摊」：到场人列表，每人可切换三种模式
  - 默认「均摊」（✓）
  - 「取消」：此人不参与本笔（—）
  - 「自定义」：输入固定应付金额（¥XX）
- 实时提示均摊结果（如：128 ÷ 2 = ¥64/人）
- 按钮「保存」

### 5. 结算结果
- 总消费 ¥X · 共 N 笔
- 每人应付清单（姓名 + 金额，精确到分）
- 按钮「完成」

### 附加：朋友名单管理
- 从聚会列表入口进入
- 添加/删除/重命名朋友

## 数据模型

所有数据存于手机浏览器本地 localStorage。金额一律以**分（整数）**存储，避免浮点误差。

### Friend（朋友）
```
{
  id: string,
  name: string
}
```
固定名单，来源是「勾选到场人」。

### Gathering（聚会）
```
{
  id: string,
  name: string,
  members: string[],     // 参与人姓名快照（来自 Friend）
  expenses: Expense[],
  settled: boolean,
  createdAt: number
}
```
聚会保存参与人姓名快照，之后从朋友名单删人也不影响历史账单。

### Expense（消费）
```
{
  id: string,
  gatheringId: string,
  title: string,         // 备注
  amount: number,        // 总金额，单位：分
  splits: Split[]       // 分摊明细
}
```

### Split（分摊明细，每人一条）
```
{
  name: string,           // 参与人姓名
  mode: "equal" | "custom" | "excluded",  // 均摊/自定义金额/不参与
  amount?: number         // mode=custom 时的固定应付（分）
}
```

## 分账计算规则（核心）

每笔消费，参与人默认**全部勾选、均摊**。支持两种微调：

- **取消勾选（excluded）**：此人本笔不参与 → 应付 0，也不占均摊人数。
- **自定义金额（custom）**：给某人指定固定应付。

计算步骤：
1. 总金额 − 所有「自定义金额」之和 = 剩余金额
2. 剩余金额 ÷ 「均摊」人数 = 每人应付（均摊）
3. 所有「自定义」的人 = 各自固定值

**精确到分（补差）**：金额按分整数存储；除不尽时（如 ¥40÷3），余下的分按顺序补到前几位，保证 **所有人应付之和 === 总消费**，一分不差。

示例：¥40 三人均摊 → 13.34 / 13.33 / 13.33（合计 40.00）。

聚会结算 = 所有 Expense 的分摊结果按人累加。

## 边界与错误处理

- 金额 ≤ 0 → 不能保存
- 一笔消费没人参与（全部 excluded）→ 不能保存
- 自定义金额为负、或「自定义之和」超过总金额 → 提示并阻止保存
- 删除朋友 → 只影响未来勾选，历史账单不受影响

## 数据备份

- 提供 JSON 导出/导入功能（整个 localStorage 数据）
- 入口在聚会列表的设置/菜单中

## 技术栈

- 手机网页 / PWA（可保存到主屏）
- 纯前端，无后端
- localStorage 存储
- 计算逻辑做成纯函数，便于测试

## 测试要点

结算算法为纯函数，重点覆盖：

1. 均摊整除（如 ¥30 ÷ 3 = ¥10/人）
2. 均摊除不尽（补差，如 ¥40 ÷ 3）
3. 取消勾选（excluded 不占人数）
4. 自定义金额（custom 固定值）
5. 自定义之和 = 0（全部均摊）
6. 自定义之和 = 总额（剩余均摊 = 0）
7. 自定义之和 > 总额 → 拒绝
8. 空参与人 → 拒绝
9. **断言**：所有情况下，每人应付之和 === 总消费（精确到分）

## 不做（YAGNI）

- 多人共同记账 / 账号登录
- 在线云同步
- 群收款文案生成
- 收款进度追踪
- 通讯录导入
- 多币种
